# 模型训练、整数参考与硬件数据说明

## 1. 先区分两种用途

**直接运行当前FPGA**使用hardware/X4的BIN和manifest；linux/model/X4是它的部署副本。不需要先训练，也不会默认读取model_data中的PTH。

**继续训练或改模型**使用model、train、dataset、model_data和export_data。

## 2. 文件夹分工

## 3. 复现当前硬件参数

在工程根目录执行：

```powershell
python -m pip install numpy pillow
python model/prepare_hardware.py
```

输入是reference/data_txt，不是PTH。输出包括hardware/X4下每层weight.bin、bias.bin、manifest.json、canonical/input_pcie.bin、canonical/expected_pcie.bin，以及../sim下的小尺寸MEM。命令会重写这些派生文件，执行前应确认确实需要再生成。

`python model/prepare_hardware.py --full-frame`另外生成../sim/full_frame的320×180测试数据。硬件文件仍会重写，详见[仿真说明](../sim/使用说明.md)。

当前板卡参数布局要点：

- 权重：逻辑字节流的每个64字节块独立倒序。
- 偏置：16个有符号int16，逻辑大端32字节整体倒序，再补32个零，形成一个DDR512数据拍。
- manifest记录八层层序、卷积核、Q0.16乘数及DDR地址；canonical每份张量为921600字节。
- 首层输入C0的有符号残差在第八层量化后加入，并在最终执行int8饱和。

若需部署同步，从根目录运行vivado_scripts/sync_linux.ps1；它还覆盖linux中的bit、ltx和测试输入，并重建清单，不只是复制模型。本次仅编写说明，没有执行再生成或同步。

## 4. 使用独立整数参考和PSNR

以下命令在工程根目录执行，结果写入新建的build/reference_check，避免重写冻结预期输出：

```powershell
New-Item -ItemType Directory -Path build/reference_check -Force
python model/reference/sim_CNN_3dic.py --data-dir model/reference/data_txt --output build/reference_check/output.txt --sr-image build/reference_check/sr.png --no-compare
```

脚本执行整数卷积、RTL量化和全局残差，恢复样本图像并与reference/dataset中的GT计算Y通道PSNR。提供`--compare 路径`可额外比对硬件输出的逻辑HEX文件；PCIe BIN需先还原64字节块顺序，不能直接当HEX比较。

该参考图像还原使用Pillow色彩转换/色度插值，而Linux C++使用自己的颜色公式和色度采样方式。因此整数张量可以作为硬件golden，参考PNG的RGB不能未经核对就当作C++输出的逐像素golden。单样本PSNR也不是整套REDS的平均指标。

## 5. 如何启动浮点与QAT训练

建议使用单独Python虚拟环境。所需模块来自现有导入：torch、torchvision、brevitas、numpy、Pillow、h5py、tqdm。依赖版本当前没有随工程冻结；GPU环境按本机CUDA/PyTorch匹配情况配置，本说明不声称已在所有组合下验证。

训练命令从本model目录执行，因为Config中的dataset、model_data路径按当前工作目录解析：

```bash
cd /工程路径/model
python -m pip install torch torchvision brevitas numpy pillow h5py tqdm
python train/train_float.py
# 完成浮点训练/部署融合并确认best_deploy.pth后，再执行
python train/train_QAT.py
```

启动前检查两个文件的Config：

1. train_hr_dir默认dataset/div2k/DIV2K_train_HR，train_lr_dir默认dataset/div2k/DIV2K_train_LR_bicubic/X4。需自行准备配对DIV2K数据，文件按排序配对，数量及对应关系必须正确。
2. eval_file默认dataset/Set5_x4.h5。EvalDataset期待lr/0、hr/0等二维灰度数组，取样时除以255。输入范围和评估张量dtype需与模型一致，不能重复归一化。
3. scale=4，d=16、s=16、m=4对应现有八层结构。更改结构会影响权重形状、导出和RTL映射。
4. 输出分别为model_data和model_data/QAT。脚本可能更新已有同名checkpoint；若继续实验，请先把Config的outputs_dir设为新的实验目录。QAT默认读取model_data/best_deploy.pth，恢复训练使用resume_file并要求配置匹配。

以上为入口与数据约定；本次没有运行训练、修改Config或覆盖checkpoint。

## 6. QAT参数导出怎么用

在本model目录执行，可先查看帮助：

```bash
python export_data/export_qat.py --help
python export_data/export_qat.py --checkpoint model_data/QAT/best_qat.pth --output-dir ../build/qat_export
```

不传硬件配置时，导出器以TXT/JSON描述为主，并标记硬件合同待确认。传`--hardware-config export_data/hardware_config.json`才按显式规则生成硬件BIN；`--verify-only`重新提取并验证既有导出，不重写。默认输出组织为逐层，其他选项以--help为准。
