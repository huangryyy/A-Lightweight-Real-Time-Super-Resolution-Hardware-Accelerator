# RTL网络与计算模块说明

本目录提供当前X4八层卷积＋全局残差设计。板级综合顶层是Top；控制器每帧调度8层，主机完成PixelShuffle和颜色恢复。

## 1. 数据怎样流动

Linux将RGB转换为量化亮度输入，按硬件布局写入DDR。top_controller锁存每层配置，调度DDR读入、片上计算和结果写回。前7层启用ReLU，最后一层关闭ReLU，并在宽量化结果上加入原输入C0的有符号残差，再执行int8饱和。输出仍是低分辨率上的16通道张量，主机将其PixelShuffle为4倍尺寸。

模型层序及量化乘数在../model/hardware/X4/manifest.json，主机也在../linux/host/FSRCNN_X4_video.cpp中配置相关参数。当前顺序是first_part.0、shrink.0、四层ecb_blocks、expand.0、last_part，卷积核分别为5、1、3、3、3、3、1、3。

## 2. 主要源码

|文件|作用及修改时关联项|
|---|---|
|Top.v|连接XDMA、DDR4、AXI及控制/计算模块；关联Core_test中的IP和管脚约束|
|top_controller.v|AXI-Lite寄存器、配置锁存和八层调度；关联C++及verify_board.py的寄存器协议|
|FSM_state.v、Control_sram_addr.v|计算过程状态及片上地址控制|
|Processing_group.v、PG_sram.v|4像素×16输入×16输出并行计算及片上缓存组织|
|Mac.v、Eg_mul.v、Acc_1.v、acc_1x16.v、adder.v|乘法、累加、求和等算术单元|
|ReLU.v|激活及量化相关数据通路|
|global_residual_store.v|保存首层输入C0供末层残差使用|
|residual_add_saturate.v|有符号残差相加与最终饱和|
|ddr_rd_core_conv_inp/weight/bias.v|输入、权重和偏置的DDR读取|
|ddr_rd_wrapper1/2/3.v|读通路封装与调度|
|ddr_wt_core_conv.v、ddr_wr_wrapper1.v|输出写回DDR|
|count.v、rd_finish_signal_gen.v|计数及读完成相关控制|
|tb_FSRCNN_X4.v|参数化逐层检查平台，不参与综合；被sim/tb_full_frame.v复用|

算术使用int8权重、uint8中间激活、int16偏置及18位MAC饱和。负数舍入、饱和位置、DDR字节序和残差符号必须与冻结整数参考保持一致，不能只按浮点网络公式替换。

## 3. 控制协议的检查入口

AXI-Lite字节偏移68返回模型ID 0x38475231，偏移84返回控制修订2。主机用偏移60发送启动/完成确认，偏移64读取完成状态。更改寄存器、层序或配置打包时，需要同步主机和verification/verify_board.py；完整实现以top_controller.v及调用方代码为准。

## 4. 如何验证修改

在工程根目录执行：

```powershell
& ./vivado_scripts/verify_rtl.ps1 -VivadoBin 'D:/Vivado/Vivado/2023.2/bin'
```

它运行逐层数值、控制/偏置与残差边界测试。整帧测试需按[sim说明](../sim/使用说明.md)准备full_frame数据。综合和实现使用[Core_test说明](../Core_test/使用说明.md)，上板测试使用[Linux说明](../linux/使用说明.md)。仅通过行为仿真还不能证明DDR、PCIe或板级时序正常。
