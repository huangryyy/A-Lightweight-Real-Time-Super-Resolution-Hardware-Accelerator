# RTL仿真数据与测试平台说明

本目录用于不连接板卡的数值和控制回归；它不模拟整块板卡的真实PCIe、DDR校准或时序收敛。

## 文件分工

|文件|用途|
|---|---|
|weights.mem、bias.mem|逐层冻结整数权重/偏置的仿真表示|
|input.mem|默认16×8小尺寸输入，包含残差符号及像素通道排列检查所需数据|
|expected0.mem～expected7.mem|八层各自的预期输出，用于定位首次出现数值差异的层|
|ip_models.v|独立仿真使用的RAM/乘法等IP行为替身|
|control_fifo_models.v|控制相关FIFO行为替身|
|tb_control_bias.v|控制配置及偏置读取相关测试|
|tb_residual_edges.v|残差相加、符号及饱和边界测试|
|tb_full_frame.v|调用Core/tb_FSRCNN_X4.v的320×180参数化整帧包装|

主逐层测试平台位于../Core/tb_FSRCNN_X4.v。行为IP只供仿真，不应加入Top的综合源。MEM与PCIe BIN的位宽/字节顺序不同，不能互换。

## 运行已有小尺寸回归

在工程根目录PowerShell执行：

```powershell
& ./vivado_scripts/verify_rtl.ps1 -VivadoBin 'D:/Vivado/Vivado/2023.2/bin'
```

脚本将现有MEM复制到build/rtl_checks，执行xvlog、xelab、xsim，测试tb_FSRCNN_X4、tb_control_bias、tb_residual_edges。各日志须出现PASS且没有FATAL或MISMATCH；汇总为RTL_CHECKS_PASS。不要仅以工具进程退出码判断算法通过。

## 重新生成数据和整帧回归

本目录现成小尺寸数据可直接使用。确需重新生成时，在工程根目录准备Python依赖：

```powershell
python -m pip install numpy pillow
python model/prepare_hardware.py
```

该命令同时重写model/hardware/X4的派生BIN和manifest，不是只写sim。输入来自model/reference/data_txt，不来自QAT checkpoint。

完整帧数据当前按需生成：

```powershell
python model/prepare_hardware.py --full-frame
& ./vivado_scripts/verify_rtl.ps1 -VivadoBin 'D:/Vivado/Vivado/2023.2/bin' -FullFrame
```

第一步创建sim/full_frame下的MEM，也重写硬件派生文件。第二步仅运行tb_full_frame。整帧仿真明显慢于小尺寸测试；硬件计算时间不能按仿真墙钟时间估计。

若中文路径影响Vivado仿真工具，可把工程映射到一个空闲ASCII盘符后从该盘符启动PowerShell和脚本，结束后解除映射；不要随意覆盖已有盘符。算法测试通过后，仍需按[顶层说明](../工程使用说明.md)执行综合实现和Linux实板验证。
