# Vivado工程说明

## 1. 保留内容

|文件或路径|用途|
|---|---|
|Core_test.xpr|现有Vivado工程入口，目标xczu19eg-ffvc1760-2-i|
|Core_test.srcs/sources_1/ip/|14个IP的XCI配置，用于重新生成IP产物|
|Core_test.srcs/constrs_1/imports/Core_test/Clock.xdc|时钟及相关约束|
|同目录ddr4.xdc、pcie.xdc|DDR4、PCIe板级约束|
|Core_test.sim/|现有仿真工作目录；实际内容以当前文件为准|

RTL实际位于../Core，不应在此另外创建一套不同版本的网络源码。XCI主要包括XDMA、DDR4控制器、AXI互连、时钟/复位、输入/输出/权重RAM、FIFO和乘法器；列表见../vivado_scripts/ip_files.txt。

## 2. 打开现有工程

在Vivado2023.2中打开Core_test.xpr，确认器件正确、综合顶层Top、仿真顶层tb_FSRCNN_X4。IP输出文件缺失时按需要Generate Output Products。不要只为消除提示就跨版本升级IP，应先确认新版本对接口和实现的影响。

在工程根目录可执行源码工程检查：

```powershell
& 'D:/Vivado/Vivado/2023.2/bin/vivado.bat' -mode batch -source ./vivado_scripts/verify_current.tcl
```

它检查器件、14个IP及锁定/缺失情况，通过标志为CLEAN_CURRENT_PROJECT_PASS；不执行完整综合或时序验证。

## 3. 从源重建

在工程根目录执行：

```powershell
# 新建工程，不综合
& 'D:/Vivado/Vivado/2023.2/bin/vivado.bat' -mode batch -source ./vivado_scripts/rebuild.tcl
# 新建工程、生成IP、综合、实现并生成bit；与上面的命令二选一
& 'D:/Vivado/Vivado/2023.2/bin/vivado.bat' -mode batch -source ./vivado_scripts/rebuild.tcl -tclargs --build
```

默认目标为build/Core_test，已有该目标工程时脚本拒绝覆盖。可加`--output D:/新的输出目录`，仅生成IP可用`--generate-ip`。执行后还会在fpga_release生成IP状态报告。

新bit位于build/Core_test/Core_test.runs/impl_1/Top.bit，时序报告位于build/Core_test/final_timing.rpt和final_bus_skew.rpt。重建不会自动覆盖现有fpga_release/Top.bit。新版本需完成时序、DDR校准、Linux整帧零差异与流水线检查，再确认部署文件。

## 4. 仿真与清理

算法及控制回归优先用../vivado_scripts/verify_rtl.ps1，详见[sim说明](../sim/使用说明.md)。sim中的IP行为模型用于独立测试，不能替代本工程综合用XCI。

../vivado_scripts/clean_generated.ps1会删除build、部分Core_test生成目录、日志等，具有实际删除行为；不是打开工程或运行程序的前置步骤。本次说明编写没有执行它。
