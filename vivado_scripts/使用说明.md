# Vivado及工程维护脚本说明

这些脚本通过自身位置寻找工程根目录，通常从根目录PowerShell调用。Vivado命令示例使用2023.2，安装路径按实际电脑调整。日常Linux超分运行不需要逐个执行本目录脚本。

## 1. 脚本用途与写入范围

|脚本|用途|主要影响|
|---|---|---|
|verify_current.tcl|打开现有Core_test.xpr，检查器件、14个IP及锁定/缺失状态|检查当前源码工程；Vivado可能生成日志|
|rebuild.tcl|从Core RTL、XCI、XDC重建工程，可选择生成IP和完整构建|默认写build/Core_test；另生成fpga_release/ip_status_after_cleanup.rpt|
|verify_rtl.ps1|独立编译并运行小尺寸或整帧RTL回归|写build/rtl_checks，不下载FPGA|
|ip_files.txt|保留的14个IP配置路径列表|供核对及清理脚本使用|
|sync_linux.ps1|把发布bit、ltx、模型和输入同步到独立Linux目录|覆盖linux相应副本，并重写linux/SHA256SUMS|
|package.ps1|按白名单生成完整项目提交归档|重写顶层SHA256SUMS和.local/dist中的列表、归档及哈希|
|clean_generated.ps1|清理已知Vivado/仿真生成物及列明的旧文件|实际删除目录和文件，并写fpga_release/cleanup_report.json|

阅读说明和使用已有bit运行，不需要执行同步、打包或清理。这里列出的修改行为仅说明脚本现状，本次没有执行这些维护动作。

## 2. 检查和构建命令

从工程根目录执行：

```powershell
& 'D:/Vivado/Vivado/2023.2/bin/vivado.bat' -mode batch -source ./vivado_scripts/verify_current.tcl
& ./vivado_scripts/verify_rtl.ps1 -VivadoBin 'D:/Vivado/Vivado/2023.2/bin'
```

第一个通过标志为CLEAN_CURRENT_PROJECT_PASS，第二个为RTL_CHECKS_PASS。两者均不代表已经通过板级DDR和PCIe验证。

重建命令：

```powershell
& 'D:/Vivado/Vivado/2023.2/bin/vivado.bat' -mode batch -source ./vivado_scripts/rebuild.tcl -tclargs --build
```

- 不传--build：只创建源码工程。
- --generate-ip：另外生成IP输出产物。
- --build：生成IP、综合、实现至write_bitstream，输出时序报告。
- --output 新目录：指定独立目标，已有同名工程时脚本拒绝覆盖。

整帧RTL测试需先从冻结参数生成数据：

```powershell
python -m pip install numpy pillow
python model/prepare_hardware.py --full-frame
& ./vivado_scripts/verify_rtl.ps1 -VivadoBin 'D:/Vivado/Vivado/2023.2/bin' -FullFrame
```

prepare_hardware.py还会重写model/hardware/X4派生文件，不能把它当成完全只读检查。详见[模型说明](../model/使用说明.md)。

## 3. 同步和打包的当前状态

sync_linux.ps1以fpga_release/Top.*、model/hardware/X4和data/lr为源。它不编译C++或驱动，也不会自动修复旧README中的路径。需要确认发布版本和部署副本一致后再运行。

package.ps1当前白名单要求docs/validation和README_VIVADO.md，但这两项在当前文件树中不存在，因此直接执行会停止并报Missing submission input；新增的顶层工程使用说明.md也不在其白名单中。当前不能把它当作无需调整即可使用的一键提交入口。本次依照“已有文件不动”的要求，没有修改脚本或生成新包。

Linux也有独立SHA256SUMS，目前仍引用26个已不存在的旧历史路径。正式发布时应确认当前文件集合后统一更新清单与打包入口，详见[顶层说明](../工程使用说明.md)。

## 4. 清理脚本的边界

clean_generated.ps1包含删除build、Core_test的若干生成目录、日志及列明旧文件的操作；它会先核对14个IP列表和发布bit哈希。只有确实要清理且已关闭Vivado/XSIM时才使用。它不是复现的必要第一步，也不能替代版本备份或新bit验证。
