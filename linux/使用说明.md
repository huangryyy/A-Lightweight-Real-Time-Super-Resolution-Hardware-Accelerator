# Linux主机执行目录说明

本目录可整体复制到连接FPGA的Linux电脑。以下命令默认在本目录执行。

## 1. 文件如何配合

|文件或目录|作用|
|---|---|
|Top.bit、Top.ltx|八层X4＋全局残差的FPGA配置与配套探针|
|host/FSRCNN_X4_video.cpp|预处理→XDMA/FPGA→PixelShuffle/颜色恢复→视频编码的C++实现|
|host/FSRCNN_X4_video|Ubuntu24.04 x86-64预编译程序；其他环境重新编译|
|host/build.sh、build.sh|编译主机；外层build.sh调用host/build.sh|
|host/CMakeLists.txt|可选CMake构建入口，需本机安装CMake|
|host/stb_image*.h|PNG读取、原始输出PNG保存及相应许可证|
|driver/|XDMA驱动源码，必须匹配当前运行内核构建|
|model/X4/|每层硬件权重、偏置、地址/量化manifest和canonical参考张量|
|data/lr/|100张320×180输入PNG|
|scripts/|驱动编译、下载前准备、JTAG下载和驱动加载|
|verification/verify_board.py|固定整帧输出与golden逐字节比较|
|host/validate_pipeline.py|串行/流水线一致性、异常退出、编码和节拍集成测试|
|reference_results/results/|当前保留的历史MP4、原始PNG及单样本PSNR|
|results/|执行后新建的结果目录，与reference_results不同|

## 2. 首次构建

```bash
sudo apt-get update
sudo apt-get install build-essential python3 pciutils ffmpeg "linux-headers-$(uname -r)"
bash build.sh
bash scripts/build_driver.sh
```

主机构建使用g++、C++17、OpenMP和pthread，生成host/FSRCNN_X4_video。驱动构建生成driver/xdma/xdma.ko。不能从另一台内核不同的电脑直接复制.ko使用。

setup.sh原本将依赖安装、文件校验和两项构建合并执行。但当前SHA256SUMS含26个不存在的旧历史路径，因此setup.sh会在校验阶段停止。上述分步命令可构建当前程序；正式迁移发布时仍应核对来源并更新清单。本次文档编写没有修改清单。

## 3. 配置和验证板卡

连接PCIe、USB/JTAG并供电。关闭其他推理程序，再执行：

```bash
sudo bash scripts/prepare_programming.sh
source /实际安装目录/Vivado/2023.2/settings64.sh
```

在另一个已加载Vivado环境的终端运行hw_server（已有localhost:3121服务时不重复启动）：

```bash
hw_server -s tcp::3121
```

回到原终端：

```bash
vivado -mode batch -source scripts/program_fpga.tcl
# 必须看到PROGRAM_AND_DDR_PASS
sudo bash scripts/load_driver.sh
bash verify.sh board
```

program_fpga.tcl下载本目录Top.bit、加载Top.ltx并检查DDR校准。多JTAG目标需使用`-tclargs '实际目标过滤条件'`指定唯一目标。load_driver.sh重新扫描PCIe，要求10ee:903f设备存在，加载XDMA并将设备节点授予调用sudo的普通用户。

board检查要求模型ID为0x38475231、控制修订为2，上传固定输入，计算并比较921600字节。成功结果写入results/board_时间戳/result.json，mismatched_bytes应为0。

## 4. 运行完整超分程序

```bash
bash run.sh
bash run.sh --fps 30
bash run.sh --repeat 10 --pace
```

run.sh默认使用本目录data/lr、model/X4，三阶段流水线、3个缓冲槽、每CPU处理阶段4个OpenMP线程、60FPS视频时间戳。缺少二进制或源码更新时自动重新编译。所有相对默认部署路径均由脚本定位，不依赖旧/home/FSRCNN目录。

|参数|效果|
|---|---|
|--fps 30或60|设置输出视频时间戳；与--pace共同确定输入节拍|
|--pace|按目标帧率等待输入时刻；不加则尽可能快地处理|
|--repeat 10|100张输入循环10次，总计1000帧|
|--mode serial|串行前处理、FPGA、后处理，供流水线对照|
|--mode pipeline|启用三阶段流水线|
|--buffers 3|主机缓冲槽数量，允许2～8；不代表多个FPGA同时计算|
|--threads 4|每个CPU处理阶段的OpenMP线程数|
|--no-video|不启动视频编码，仍执行超分并记录指标|
|--checksums|记录FPGA输出和RGB的FNV哈希，会增加校验开销|
|--input /新目录|使用其他连续PNG序列，也可指向单张合规PNG|

如需指定FFmpeg：`FFMPEG=/工具路径/ffmpeg bash run.sh`。

直接调用C++二进制时，需自行传入输入、权重与互不冲突的输出路径，例如：

```bash
out="results/manual_$(date +%s%N)"
mkdir -p "$out"
./host/FSRCNN_X4_video --input data/lr --weights model/X4 \
  --mode pipeline --buffers 3 --threads 4 --fps 60 \
  --output "$out/video.mp4" --csv "$out/frames.csv" \
  --summary "$out/summary.json" --snapshots "$out/snapshots"
```

编码为H264、ultrafast、CRF18、YUV420P。不是无损RGB，但没有额外生成低码率预览。若评估模型精度，使用原始PNG，不从MP4解码后计算模型PSNR。

## 5. 输出怎样看

- video.mp4：超分结果，1280×720。只设置60FPS不代表已经实现60FPS实时处理。
- frames.csv：逐帧解码、预处理、H2C、配置、FPGA、C2H、后处理、编码管道及排队耗时。
- summary.json：总吞吐、输出间隔、帧驻留延迟和各阶段均值。end_to_end_fps包含编码收尾，output_interval反映输出节拍。
- snapshots/：第一遍输入的首帧、中间帧和末帧PNG；不是全部100帧。

frame_ms/source_latency包含排队，流水线中可能超过16.67ms而仍每16.67ms输出一帧。frames_over_budget不是丢帧数量。程序不计算全部输入的GT PSNR，也不自动连接摄像头或显示窗口。

## 6. 重新测试流水线

```bash
bash verify.sh pipeline
# 使用自带工具时同时指定ffmpeg与ffprobe所在目录
FFMPEG_TOOLS=/工具目录 bash verify.sh pipeline
```

该测试默认要求100张输入，比较串行100帧与流水线300帧的原始张量/RGB哈希，并执行故障退出及1000帧串行、流水线和60FPS节拍测试。输出在results/validation_时间戳/。此步骤会实际运行FPGA，应在board验证通过后执行。

`bash verify.sh files`只按已有SHA256SUMS检查文件；当前旧路径缺失情况见第2节。

## 7. 已有视频与常见问题

历史视频为reference_results/results/videos/30FPS.mp4、60FPS.mp4、LR_vs_X4.mp4。对比视频含标题栏；images/comparison_frame50.png中间故意保留旧模糊预览用于说明压缩损失，不能将中间图当成当前输出。

|现象|处理位置|
|---|---|
|lspci查不到10ee设备|检查供电、PCIe连接、bit下载及枚举；部分主机需板卡保持供电后重启主机再扫描|
|存在PCIe设备但没有/dev/xdma0_*|重新构建并加载匹配内核的驱动，检查终端错误和内核日志|
|Permission denied|用普通账户执行sudo bash scripts/load_driver.sh，再运行程序|
|模型ID/控制修订不匹配|确认下载本目录Top.bit，且权重与协议配套|
|FPGA timeout|先保存状态并检查DDR、控制器和bit，不连续重试覆盖现场|
|输入尺寸或命名错误|必须320×180；PNG名为连续八位数字，如00000000.png|
|找不到ffmpeg/ffprobe|安装软件，或分别配置FFMPEG及FFMPEG_TOOLS|

如果板卡和程序都已配置好，后续通常只需run.sh。板卡掉电、重新下载bit、主机重启或驱动卸载后，应重新检查配置、枚举和设备权限。
